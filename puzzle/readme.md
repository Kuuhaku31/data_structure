# 基于 BFS 算法的八数码问题求解程序

## 一、问题简介

八数码问题是人工智能领域中一个经典的路径搜索与状态空间探索问题。该问题由一个 3x3 的棋盘构成，包含 8 个带数字的方块（编号为 1 至 8）和一个空格（通常以数字 0 表示）。游戏的目标是通过移动空格的位置，使得棋盘从任意给定的初始状态转变为指定的目标状态（一般默认为 `123456780`）。

这种问题在搜索算法、图遍历和启发式策略设计等多个计算机科学分支中都有广泛应用，因此是教学与科研中的常见案例。

## 二、程序概述

本程序使用 **C++** 编写，设计为一个简洁而高效的 3x3 拼图求解器。核心采用 **BFS（Breadth-First Search，广度优先搜索）** 算法，通过层层扩展搜索图的每一个可能状态，从而实现从初始状态到目标状态的最短路径查找。

程序运行过程中，将会记录所有访问过的状态及其路径信息，并将最终求得的路径结果输出至 `path.txt` 文件中。同时，所有中间访问的状态及其哈希组织结构也会记录在 `state_map.txt` 文件中，供进一步分析。

### 项目结构

- `header.h`：状态表示和操作定义
- `puzzle.cpp`：主程序文件，包含各个方法以及 BFS 算法实现
- `main.cpp`：程序入口，处理命令行参数和输出结果
- `readme.md`：项目说明文档

## 三、运行方式

程序以命令行方式运行，格式如下：

```bash
./puzzle.exe 283164705 123456780
```

其中，`283164705` 表示初始状态，`123456780` 表示目标状态。如果用户未提供目标状态，则程序默认以 `123456780` 为目标。

程序运行完毕后，将输出以下两个文件：

- `path.txt`：记录求解出的最短路径及各步详细操作；
- `state_map.txt`：记录程序在搜索过程中访问的所有状态，按哈希桶结构组织。

## 四、功能模块说明

### 1. 状态 State 模块

该模块用于表示拼图的当前状态，采用长度为 9 的一维数组或整数进行编码，其中 0 表示空格的位置。状态之间的比较、哈希等操作基于该编码实现。

### 2. 操作 Operate 模块

定义枚举类型 Operate 表示移动方向：上 (0)、右 (1)、下 (2)、左 (3)。该枚举用于指导空格的移动方向，从而生成新的状态。

### 3. 节点 Node 模块

每个 Node 表示搜索图中的一个节点，包含当前状态、指向前驱节点的指针、从前驱节点到当前节点所执行的操作、路径步数等信息。该结构便于进行路径回溯与构建解路径。

成员变量包括：

- `deep`：当前节点的深度（步数）；
- `current_state`：当前状态的编码；
- `last_state`：上一个状态的编码；
- `operate`：从上一个状态到当前状态的操作方向；
- `last_list_node` 和 `next_list_node`：用于队列 LinkList 的双向链表指针；
- `last_map_node` 和 `next_map_node`：用于状态映射表的双向链表指针。

### 4. 队列 LinkQueue 模块

自定义链表结构，作为 BFS 的工作队列使用。提供入队（push）、出队（pop）等基本操作，保证算法在状态空间中的广度优先遍历。

### 5. 状态映射表 StateMap 模块

基于哈希表实现，用于记录所有已访问的状态以防止重复扩展。状态以哈希桶方式存储，查找与插入效率高，极大提升了程序性能。

## 五、算法流程

整个 BFS 解题流程如下：

1. **输入读取**：从命令行获取初始状态与目标状态；
2. **初始化数据结构**：包括 BFS 队列、状态映射哈希表等；
3. **初始节点入队**：将初始状态构造为节点，加入队列并记录；
4. **执行 BFS 搜索**：

   - 从队列头部取出当前节点；
   - 根据四个方向枚举可行的状态移动操作；
   - 检查新状态是否已存在于状态映射表中：

     - 若未访问，则插入映射表，构造新节点并入队；

   - 若新状态与目标状态匹配，则终止搜索；

5. **路径回溯**：从目标状态节点依次回溯至初始节点，生成完整的路径操作序列。

## 六、结果保存格式

### 1. 路径文件 `path.txt`

该文件详细记录了从初始状态到目标状态的每一步操作，包括每步操作方向及执行后的拼图状态示意。例如：

```text
第 1 步:
向上划动:
| 1 | 2 | 3 |
| 4 | 5 | 6 |
| 7 | 8 | 0 |
...
```

该文件便于用户对求解过程进行可视化理解与复现。

### 2. 状态映射文件 `state_map.txt`

该文件记录所有访问过的状态，并以哈希桶的形式分类，内容示例如下：

```text
哈希桶[0000] -> 325814706 -> 456831720 -> NULL
哈希桶[0001] -> 571036482 -> 867420153 -> 418035672 -> 264307815 -> NULL
哈希桶[0003] -> 087643521 -> 863074125 -> 847053612 -> NULL
哈希桶[0004] -> 574183260 -> 756243180 -> 741352860 -> NULL
...
```

该结构有助于调试、验证状态去重机制及观察哈希分布情况。

## 七、结构与性能分析

本程序具有如下结构设计优点与性能特点：

- **操作编码简洁统一**：操作方向以 0\~3 编码，便于程序处理；
- **BFS 确保最优路径**：由于 BFS 的特性，程序能保证找到从初始状态到目标状态的最短路径；
- **模块化设计清晰**：状态表示、节点结构、操作逻辑、队列管理、状态映射等均为独立模块，便于维护与拓展；
- **高效状态去重机制**：借助哈希表快速查重，显著提升搜索效率；
- **避免冗余搜索**：通过状态映射表有效避免重复访问，节省内存与计算资源；
- **适用于教学与演示**：未采用启发式策略，结构清晰，适合初学者理解搜索算法原理。

## 八、总结

综上所述，本八数码问题求解程序不仅在实现上遵循了 BFS 算法的核心原则，也在结构上体现出清晰的模块划分与高效的状态管理机制，具备良好的扩展性与实用价值。程序以命令行接口为基础，支持灵活调用，并通过文件输出的方式提供详尽的路径与状态数据，极大地方便了用户的理解与调试。

本项目非常适合对人工智能、搜索算法、图遍历技术感兴趣的开发者和学生作为入门学习的案例，也适合用于算法教学、程序设计训练等实践活动。随着未来进一步的拓展，如引入启发式搜索策略（如 A\* 算法）、支持更大规模的拼图场景或加入图形界面，本程序将具备更强的实用性与教育价值，成为算法学习过程中一项经典而有代表性的项目。
